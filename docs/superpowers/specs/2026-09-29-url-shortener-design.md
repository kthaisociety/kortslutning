# kortslutning — ktha.is URL shortener: design

- **Date:** 2026-09-29
- **Status:** Approved in brainstorming; pending written-spec review

## 1. Intent

KTH AI Society members need a way to create short, memorable links on the
society's own domain (`ktha.is/apply`, `ktha.is/x7k2p`) for posters, slides,
social media and messages.

**Success looks like:** a member signs in on `app.ktha.is` with their
`@kthais.com` Google account, creates `ktha.is/foo → https://…`, and anyone on
the internet visiting `ktha.is/foo` is redirected. Google accounts outside
`@kthais.com` cannot sign in.

### Stated requirements

- Next.js full-stack web app.
- Google SSO; every `@kthais.com` account can sign in and create short links.
  Credentials via `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`.
- `ktha.is` is public and serves redirects; `app.ktha.is` hosts sign-in and link
  management.
- PostgreSQL, connection string in `DB_URL`; `docker-compose.yaml` for local setup.

### Decisions made during brainstorming

| Topic | Decision |
|---|---|
| Permissions | Any signed-in member can create, edit and delete **any** link. `created_by` / `updated_by` are recorded. |
| Slugs | Custom slug, or a random one when left blank. Immutable after creation. Case-insensitive. |
| Analytics | Per-link click counter and last-clicked timestamp. No per-click log. |
| `ktha.is/` (root) | 307 redirect to `ROOT_REDIRECT_URL` (the society's main site). |
| Unknown slug | Branded "link not found" page, HTTP 404. |
| Stack | Next.js 16 (App Router) + Better Auth + Drizzle ORM + PostgreSQL. |
| QR codes | Included in v1 (SVG + PNG download). |
| CI | GitHub Actions: lint, typecheck, test, build on push/PR. |

### Assumptions

- One Next.js app, one container, serves both hostnames and routes by `Host` header.
- Redirects are temporary (307) so targets can be changed without browsers
  caching the old destination.
- Hosting/DNS provisioning is out of scope; the deliverable is a Docker image
  built from the existing `Dockerfile`, plus deployment notes.
- Match sibling KTH AIS repos: TypeScript, Tailwind CSS 4, shadcn/ui, npm (the
  existing `Dockerfile` uses `npm ci` and `package-lock.json`). No second lockfile.

## 2. Architecture

A single Next.js 16 App Router application with `output: "standalone"`
(required by the existing `Dockerfile`).

```
                 ┌──────────────────────── Next.js app (one container) ────────────────────────┐
 ktha.is/foo ──▶ │ proxy.ts ──routeRequest(host, path)──▶ rewrite /r/foo ──▶ app/r/[slug]/page │──▶ 307 Location: target
                 │                                                                              │
 app.ktha.is ──▶ │ proxy.ts ──▶ pass through ──▶ dashboard pages, server actions, /api/auth/*   │
                 └──────────────────────────────────────┬───────────────────────────────────────┘
                                                        ▼
                                                   PostgreSQL
```

### 2.1 Host routing

`src/proxy.ts` (Next.js 16's replacement for `middleware.ts`) delegates to a pure
function `routeRequest(host, pathname)` in `src/lib/routing.ts`, which returns a
decision (`redirect`, `rewrite`, `notFound`, `next`). The short host and app host
are derived from `SHORT_URL` and `APP_URL`.

| Host | Path | Decision |
|---|---|---|
| short host | `/` | `redirect` 307 → `ROOT_REDIRECT_URL` |
| short host | `/<segment>` where segment contains no `.` and no further `/` | `rewrite` → `/r/<segment>` |
| short host | `/<segment>` where segment contains a `.` (e.g. `/favicon.ico`, `/robots.txt`) | `next` (static asset) |
| short host | anything else (multi-segment paths, including dotted ones) | `notFound` |
| any other host | `/r` or `/r/*` | `notFound` (redirects only resolve on the short host) |
| any other host | anything else | `next` (normal app) |

Any host other than the short host is treated as the app host, so health checks
and reverse-proxy host variations do not break the app. The proxy matcher
excludes `/_next/*` so the 404 page's assets load on the short host.

Slug normalization (lowercasing) happens in the redirect page, not the proxy.
Because the short host never serves app pages, slugs such as `login` or `api`
do not collide with app routes and no slugs are reserved.

### 2.2 Redirect page

`src/app/r/[slug]/page.tsx` is a dynamic server component (never statically
cached):

1. Lowercase the slug param. If it fails slug validation, call `notFound()`.
2. Execute one atomic statement:
   `UPDATE links SET click_count = click_count + 1, last_clicked_at = now() WHERE slug = $1 RETURNING target_url`.
3. Row returned → `redirect(target_url)` (HTTP 307 with `Location`).
   No row → `notFound()` (branded 404 page, HTTP 404).

Link unfurlers (Slack/Discord previews) count as clicks; accepted.

## 3. Data model

Defined as a Drizzle schema in `src/lib/db/schema.ts`; migrations generated by
`drizzle-kit generate` into `drizzle/` and committed.

### 3.1 `links`

| Column | Type | Constraints / notes |
|---|---|---|
| `slug` | `text` | Primary key. Stored lowercase. Check constraint matching `^[a-z0-9](?:[a-z0-9-]{0,62}[a-z0-9])?$` (1–64 chars, `a-z0-9-`, no leading/trailing hyphen). |
| `target_url` | `text` | Not null. |
| `click_count` | `integer` | Not null, default `0`. |
| `last_clicked_at` | `timestamptz` | Nullable. |
| `created_by` | `text` | FK → `user.id`, `ON DELETE SET NULL`. |
| `updated_by` | `text` | FK → `user.id`, `ON DELETE SET NULL`. |
| `created_at` | `timestamptz` | Not null, default `now()`. |
| `updated_at` | `timestamptz` | Not null, default `now()`; set explicitly on update. |

### 3.2 Rules

- **Slugs are immutable.** Editing a link changes only `target_url`. To "rename",
  create a new link and delete the old one. Rationale: renaming silently breaks
  printed posters/QR codes, and with shared editing that is easy to do by accident.
- **Case-insensitive.** All slug input is lowercased before validation, storage
  and lookup; `ktha.is/AI-Day` resolves the same as `ktha.is/ai-day`.
- **Random slugs.** 6 characters from the unambiguous alphabet
  `23456789abcdefghjkmnpqrstuvwxyz` (31⁶ ≈ 887M combinations). On a unique
  violation, retry with a new random slug up to 5 times, then fail with a
  generic error.
- **Hard delete.** Deleting frees the slug for reuse. No soft-delete flag.

### 3.3 Better Auth tables

`user`, `session`, `account`, `verification`, generated as a Drizzle schema by the
Better Auth CLI into `src/lib/db/auth-schema.ts`, migrated through the same
`drizzle-kit` flow as `links`.

## 4. Authentication

Better Auth with the Google social provider, Drizzle adapter, Postgres-backed
sessions. Handler mounted at `src/app/api/auth/[...all]/route.ts`.

### 4.1 Domain restriction (two server-side layers)

1. **Google provider:** `hd: "kthais.com"`. Focuses Google's account picker on
   society accounts; Better Auth rejects ID tokens without a hosted-domain claim.
2. **User creation hook:** `databaseHooks.user.create.before` aborts user creation
   unless the email ends with `@kthais.com` **and** Google reports it verified.
   Because no `user` row can exist without passing this check, no session can be
   issued to an outside account.

The allowed domain is a code constant (`ALLOWED_EMAIL_DOMAIN = "kthais.com"`) in
`src/lib/auth/domain.ts`, alongside a pure `isAllowedEmail(email, verified)`
function used by the hook.

### 4.2 Sessions

- Stored in Postgres; httpOnly cookie scoped to the app host.
- Fixed 7-day expiry with no rolling refresh (`session.disableSessionRefresh`):
  members sign in again once a week. Rolling refresh was rejected in the final
  review because it would let a removed member who keeps using the app stay
  signed in indefinitely.
- Offboarding: a removed Workspace account cannot sign in again; any live session
  expires within 7 days. For immediate revocation, delete the user row (README),
  which cascades to their sessions and accounts.

### 4.3 Route protection

- `requireUser()` (`src/lib/auth/require-user.ts`) fetches the session server-side
  and redirects to `/login` if absent; returns the user otherwise.
- Called in the dashboard route-group layout **and** at the start of every server
  action and authenticated route handler (server actions are directly callable
  endpoints, so layout checks alone are insufficient).
- The proxy does no auth checks.

### 4.4 Login page

`/login`: a single "Sign in with Google" button. If sign-in is rejected (wrong
domain or unverified email), the page shows "Only @kthais.com accounts can sign
in." Signed-in users visiting `/login` are redirected to `/`.

## 5. Dashboard and link management

All pages below live on the app host inside an authenticated route group.

### 5.1 Pages

- **`/` — Dashboard**
  - Create form: optional slug (visual `ktha.is/` prefix) + target URL.
    On success, show the new short link with a copy button.
  - Table of all links, newest first: short link + copy button, target
    (truncated), click count, last clicked, created by (name), updated at, QR
    icon linking to the edit page.
  - Search box: `?q=` query param, server-side `ILIKE` on `slug` and `target_url`.
  - No pagination in v1.
- **`/links/[slug]` — Edit page**
  - Slug read-only; target URL editable.
  - Stats: click count, last clicked, created by/at, updated by/at.
  - QR code (see 5.4).
  - Delete button with confirmation dialog.
- **Header:** signed-in user's name and avatar, sign-out button.

### 5.2 Server actions

`createLinkAction`, `updateLinkAction`, `deleteLinkAction` in
`src/lib/links/actions.ts`. Each:

1. calls `requireUser()`,
2. calls the link service (`src/lib/links/service.ts`), which validates input
   with the shared rules in `validation.ts` and calls the repository
   (`src/lib/links/repository.ts`),
3. revalidates affected paths.

The service layer holds the create/update/delete rules (including random-slug
retries) so they are integration-testable without the Next.js runtime.

Forms use React's `useActionState` to render field errors inline. No client-side
validation library.

### 5.3 Validation (`src/lib/links/validation.ts`)

- **Slug:** trimmed, lowercased, then must match
  `^[a-z0-9](?:[a-z0-9-]{0,62}[a-z0-9])?$`. Empty → generate random slug.
- **Target URL:** trimmed; must parse with `new URL()`; protocol `http:` or
  `https:`; length ≤ 2048; host must not equal the short host (prevents redirect
  loops and chains).
- **Taken slug:** enforced by the primary key. The repository maps a unique
  violation on a custom slug to a typed "slug taken" result; the action shows
  "ktha.is/<slug> is already taken."

### 5.4 QR codes

- Rendered server-side with the `qrcode` npm package. Content is the **short URL**
  (`${SHORT_URL}/<slug>`), never the target, so scans pass through the click
  counter and the target can change without reprinting.
- Edit page shows the QR code as inline SVG, with two download buttons:
  **SVG** (scalable; recommended for print) and **PNG** (1024 px).
- Downloads served by `GET /api/qr/[slug]?format=svg|png`
  (`src/app/api/qr/[slug]/route.ts`): calls `requireUser()`, returns 404 if the
  slug does not exist, 400 for an unknown format, otherwise the image with
  `Content-Disposition: attachment; filename="ktha.is-<slug>.<ext>"`
  (filename uses the short host).
- Error-correction level M, 4-module quiet zone.

### 5.5 UI

Tailwind CSS 4 + shadcn/ui (button, input, table, dialog, toast via sonner),
consistent with the sibling KTH AIS repos. Logo and favicon copied from
`landingpage-frontend/public/kthais-logo.svg` and `favicon.svg`. Clean and
functional; no bespoke design system.

## 6. Configuration

Validated at startup with zod in `src/lib/env.ts`; the app refuses to start and
names the missing/invalid variable.

| Variable | Example (production) | Purpose |
|---|---|---|
| `DB_URL` | `postgres://…` | PostgreSQL connection string |
| `GOOGLE_CLIENT_ID` | | Google OAuth client ID |
| `GOOGLE_CLIENT_SECRET` | | Google OAuth client secret |
| `BETTER_AUTH_SECRET` | 32+ random bytes | Signs session cookies |
| `APP_URL` | `https://app.ktha.is` | Better Auth base URL; app host derived from it |
| `SHORT_URL` | `https://ktha.is` | Short host derived from it; used to display/copy links and in QR codes |
| `ROOT_REDIRECT_URL` | `https://kthais.com` | Target for `ktha.is/` |

Tests additionally read `TEST_DB_URL` (not required by the app itself).

`.env.example` lists all variables with local-development defaults:
`APP_URL=http://localhost:3000`, `SHORT_URL=http://short.localhost:3000`,
`DB_URL` pointing at the compose Postgres. Browsers resolve `*.localhost` to
loopback, so no `/etc/hosts` edits are needed.

## 7. Local development and deployment

### 7.1 docker-compose.yaml

- `db`: `postgres:18-alpine`, healthcheck via `pg_isready`, named volume mounted
  at `/var/lib/postgresql` (Postgres 18 image layout), port 5432 exposed.
  An init script creates a second database for integration tests.
- `app`: built from the existing `Dockerfile`, `depends_on: db` with
  `condition: service_healthy`, reads `.env`, port 3000.

Workflows:
- Development: `docker compose up -d db`, then `npm run dev`.
- Production-image smoke test: `docker compose up --build`.

### 7.2 Migrations

- Authoring: `npm run db:generate` (`drizzle-kit generate`) writes SQL to
  `drizzle/`; committed.
- Applying: automatically at server startup from `src/instrumentation.ts`
  (`register()`, Node.js runtime only) using `migrate()` from
  `drizzle-orm/node-postgres/migrator`. No `drizzle-kit` needed in the production
  image. Suitable for a single running instance.
- Manual: `npm run db:migrate` for local use.

### 7.3 Docker image

- The existing `Dockerfile` is kept unchanged. `next.config.ts` sets
  `outputFileTracingIncludes: { "/*": ["./drizzle/**/*"] }` so the migrations
  folder ships inside `.next/standalone`, which the Dockerfile already copies.
- A new `.dockerignore` excludes `node_modules`, `.next`, `.git` and `.env*`
  files, so local secrets never enter the build context or image layers.
- `HOSTNAME` must stay `0.0.0.0` (the Dockerfile default). Verified during
  planning: when `HOSTNAME` is a loopback IP such as `127.0.0.1`, Next.js treats
  the proxy's internal rewrites as external requests and every slug returns 404.

## 8. Error handling

| Situation | Behaviour |
|---|---|
| Missing/invalid env var | Process fails at startup with the variable named |
| Validation error in a form | Inline field error |
| Custom slug already taken | Inline: "ktha.is/<slug> is already taken." |
| Update/delete of a link deleted concurrently | "This link no longer exists." |
| Concurrent edits | Last write wins |
| Unexpected server-action error | Logged server-side; generic error toast |
| Database unavailable during redirect | Branded `error.tsx`, HTTP 500 |
| Sign-in rejected | `/login` shows the domain message |

## 9. Testing

Vitest.

- **Unit (pure logic):**
  - slug normalization and validation;
  - target URL validation, including the self-host loop check;
  - random slug generator (length, alphabet);
  - `isAllowedEmail` (domain match, case, verified flag, look-alike domains such
    as `evil-kthais.com` and `kthais.com.evil.io`);
  - `routeRequest` across the full routing table in 2.1.
- **Integration (real Postgres via `TEST_DB_URL` — the compose test database
  locally, the service container in CI — migrated before the suite, truncated
  between tests):** link repository — create with
  custom slug, create with random slug, taken-slug result, random-slug collision
  retry, update, delete, resolve-and-increment (count and timestamp change;
  unknown slug returns nothing), search.
- **Smoke test (`npm run smoke`, `scripts/smoke.mjs`):** starts the real
  standalone build against Postgres and checks the routing table in 2.1 over HTTP
  with real `Host` headers (short-host redirect, case-insensitive slug, 404s,
  `/r/*` blocked on the app host, unauthenticated dashboard redirect to
  `/login`, click counting). Unit tests of `routeRequest` cannot catch
  rewrite-level failures such as the `HOSTNAME` issue in 7.3.
- **Manual checklist in README:** real Google sign-in succeeds with an
  `@kthais.com` account and is rejected for a non-`@kthais.com` account; redirect
  works on the short host; QR download opens and scans.
- **Definition of done:** `npm run lint`, `npm run typecheck`, `npm test`,
  `npm run build` all pass.

## 10. CI

`.github/workflows/ci.yml`, on push to `main` and on pull requests:
`npm ci` → lint → typecheck → test (with a `postgres:18-alpine` service container
for integration tests) → build (with no app environment variables, as in the
Docker build) → smoke test. A second job builds the Docker image.

## 11. Documentation deliverables

`README.md` must include:

1. Local setup (compose, `.env`, dev server, migrations, tests).
2. Environment variable reference (section 6).
3. **Google Cloud OAuth setup (manual step):** creating the OAuth client in a
   Google Cloud project, authorized redirect URIs
   `https://app.ktha.is/api/auth/callback/google` and
   `http://localhost:3000/api/auth/callback/google`, setting the OAuth consent
   screen to **Internal** when the project belongs to the kthais.com Workspace, and
   where to put the resulting client ID/secret.
4. Deployment notes: DNS for `ktha.is` and `app.ktha.is` both pointing at the
   container; reverse proxy must pass the original `Host` header; keep
   `HOSTNAME=0.0.0.0`; generating `BETTER_AUTH_SECRET`; migrations run on boot.
5. The manual test checklist from section 9.

## 13. Out of scope (v1)

Per-click analytics, link expiry, API/tokens, bulk import, audit history beyond
`created_by`/`updated_by`, admin roles, pagination, custom domains, soft delete.
